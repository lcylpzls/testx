# 竞品调研

> 结论先行：testx 不追求与 testify / go-cmp 的 API 兼容，只吸收经过验证的
> 断言语义，围绕 errx 结构化错误与家族自用场景做轻量、零魔法的测试库。

## 调研对象

| 库 | 定位 | 值得借鉴 | 自用场景下的短板 |
| --- | --- | --- | --- |
| testify/assert | 最流行的断言库 | 语义化断言名（Equal/NotNil/ErrorIs）、表格驱动、`require`/`assert` 分层 | 依赖重、消息模板偏英文、与 errx 结构化断言需要二次封装 |
| go-cmp | 深度比较库 | 可读 diff、选项化比较 | 仅比较、无断言与辅助；API 较重 |
| 标准库 testing | Go 官方测试框架 | 子测试、Cleanup、Setenv、TempDir | 无断言语义，样板代码多 |

## 自研原则

1. **家族一致**：错误断言直接理解 errx 错误码/分类/字段，日志与输出用简体中文；
2. **轻量零魔法**：断言即函数，无全局状态、无反射过度；
3. **可替换 TB**：断言基于 `testx.TB` 接口（Helper/Errorf/Fatalf 子集），
   库自身测试可用替身，不依赖 `testing.TB` 的私有方法；
4. **辅助成体系**：捕获输出、临时环境、并发执行、表格驱动统一提供；
5. **确定性消息**：失败消息含实际/期望值与类型信息，便于快速定位。
